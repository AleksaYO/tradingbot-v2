# Следующие шаги после запуска бота

## ✅ Текущий статус

Бот успешно запущен и получает рыночные данные через WebSocket. Это нормально!

## 📊 Что происходит сейчас

1. **WebSocket подключение** - бот получает данные в реальном времени:

   - Свечи (Kline) - для анализа
   - Сделки (AggTrade) - для анализа объема
   - Стакан заявок (Depth) - для определения цены

2. **Анализ данных** - бот анализирует свечи и ищет торговые сигналы по стратегии SMC

3. **Генерация сигналов** - когда условия выполнены, бот создаст торговый сигнал

## 🔍 Как проверить, что бот работает правильно

### 1. Проверьте логи на наличие важных событий:

**Ожидаемые логи:**

```
[INFO] Starting Trading Bot...
[INFO] DataFeed started
[INFO] DataFeed reconnected (если было переподключение)
[DEBUG] Processed closed kline: ... (при закрытии свечи)
```

**Если видите сигналы:**

```
[INFO] SMC signal: {...}
[INFO] SMC Entry Signal: LONG @ 104500.00, SL: 104000.00, TP: 105000.00
```

### 2. Проверьте, что свечи обрабатываются:

Бот должен обрабатывать закрытые свечи. Проверьте логи на наличие:

```
[DEBUG] Processed closed kline: ...
```

Если таких логов нет - возможно, свечи еще не закрылись (зависит от таймфрейма).

### 3. Проверьте файл логов:

```bash
tail -f logs/tradingbot.log
```

## ⚙️ Настройка для лучших результатов

### 1. Убедитесь, что накопилось достаточно свечей

SMC стратегия требует минимум 10-20 свечей для анализа. Бот начнет генерировать сигналы только после накопления достаточного количества данных.

**Время ожидания:**

- Для 1-минутных свечей: ~10-20 минут
- Для 5-минутных свечей: ~50-100 минут
- Для 15-минутных свечей: ~2.5-5 часов

### 2. Проверьте параметры стратегии

Текущие настройки в `.env`:

- `SYMBOL=BTCUSDT` - торгуемая пара
- `MAX_POSITION_SIZE=0.02` - размер позиции
- `STOP_LOSS_PERCENT=0.5` - стоп-лосс 0.5%
- `TAKE_PROFIT_PERCENT=1.2` - тейк-профит 1.2%

### 3. Настройте уровень логирования

Если хотите видеть больше информации:

```env
LOG_LEVEL=debug  # Показывает все логи
```

Если хотите только важное:

```env
LOG_LEVEL=info   # Только важные события
```

## 🎯 Что делать дальше

### Вариант 1: Ждать сигналов (рекомендуется)

1. **Оставьте бота работать** - он будет анализировать рынок
2. **Мониторьте логи** - следите за появлением сигналов
3. **Проверяйте файл логов** - `tail -f logs/tradingbot.log`

### Вариант 2: Тестирование в DRY_RUN режиме

Если хотите увидеть, как бот будет торговать:

1. Убедитесь, что `DRY_RUN=true` в `.env`
2. Дождитесь первого сигнала
3. Проверьте логи - должны увидеть:
   ```
   [INFO] Signal generated: {...}
   [INFO] [DRY RUN] Executing BUY order: ...
   ```

### Вариант 3: Проверка работы компонентов

Можно проверить, что все компоненты работают:

1. **DataFeed** - получает данные ✅ (уже работает)
2. **StrategyEngine** - анализирует данные (работает в фоне)
3. **RiskManager** - проверяет сигналы (сработает при появлении сигнала)
4. **OrderExecutor** - исполняет ордера (сработает в DRY_RUN или LIVE режиме)

## ⚠️ Важные моменты

1. **Сигналы не появляются постоянно** - это нормально! SMC стратегия ждет определенных условий:

   - BOS (Break of Structure)
   - Order Block
   - Возврат цены в Order Block

2. **Первый сигнал может появиться через несколько часов** - зависит от рыночных условий

3. **В DRY_RUN режиме** - бот не торгует реальными деньгами, только симулирует

4. **Мониторинг важен** - следите за логами, чтобы видеть работу бота

## 🚀 Готовность к LIVE торговле

Перед переходом в LIVE режим:

1. ✅ Протестируйте минимум 1-2 дня в DRY_RUN
2. ✅ Убедитесь, что сигналы генерируются корректно
3. ✅ Проверьте, что логи понятны
4. ✅ Начните с минимальных сумм
5. ✅ Установите `DRY_RUN=false` только когда будете готовы

## 📝 Команды для мониторинга

Эти команды работают в любом shell (bash, zsh, fish) и в любом терминале (iTerm2, Terminal, VS Code и т.д.):

```bash
# Смотреть логи в реальном времени
tail -f logs/tradingbot.log

# Проверить последние 50 строк логов
tail -n 50 logs/tradingbot.log

# Поиск сигналов в логах
grep "SMC signal" logs/tradingbot.log

# Поиск ошибок
grep "ERROR" logs/tradingbot.log

# Поиск с подсветкой (если установлен ripgrep)
rg "SMC signal" logs/tradingbot.log

# Смотреть логи с цветной подсветкой (если установлен bat)
bat logs/tradingbot.log
```

**Для iTerm2 (zsh):** Все команды выше работают без изменений. iTerm2 использует zsh, но стандартные Unix команды (`tail`, `grep`, `cat`) работают одинаково.

**Альтернативные варианты для iTerm2:**

```zsh
# Использование встроенных возможностей zsh
cat logs/tradingbot.log | grep "SMC signal"

# С цветной подсветкой (если установлен bat через Homebrew)
bat --follow logs/tradingbot.log

# Или используя less с поиском
less +F logs/tradingbot.log  # Нажмите Ctrl+C для выхода из режима follow
```
